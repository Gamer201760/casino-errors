# Casino Simulation

Симуляция казино с игроками и гусями. Гуси могут атаковать игроков, воровать их деньги, объединяться в стаи и оглушать противников. Игроки делают ставки, выигрывают или проигрывают, а иногда впадают в панику и теряют все деньги.

## Требования

- Python 3.13+
- uv (менеджер пакетов)
- make

## Установка

```bash
git clone <repository-url>
cd casino
make install
```

## Использование

Запуск симуляции с параметрами по умолчанию (200 шагов):

```bash
make run
```

Запуск с указанием количества шагов:

```bash
uv run main.py --steps 100
uv run main.py --steps 1000
```

Логи записываются в `casino.log`.

## Конфигурация

Все параметры симуляции настраиваются в [`config.yaml`](config.yaml):

### Генерация сущностей

- `seed` — сид генератора случайных чисел (если < 1, то сид рандомный)
- `generate_player_count` — количество игроков (max 30)
- `generate_player_max_bal` — потолок начального баланса игрока
- `generate_player_max_lucky` — потолок удачи игрока
- `generate_goose_count` — количество гусей (max 30)
- `generate_war_goose_p` — вероятность генерации атакующего гуся
- `generate_goose_max_lucky` — потолок удачи гуся
- `generate_goose_max_bal` — потолок начального баланса гуся
- `generate_goose_max_strenght` — потолок силы атакующего гуся
- `generate_goose_max_honk_volume` — потолок громкости кричащего гуся

### Параметры казино

- `casino_base_bal` — начальный баланс казино
- `bet_min` — минимальная ставка
- `bet_max_fraction` — максимальная ставка как доля от баланса игрока (0.0..1.0)
- `bet_win_multiplier_max` — максимальный множитель выигрыша
- `bet_win_base` — базовая вероятность выигрыша ставки
- `bet_win_lucky_scale` — коэффициент влияния удачи на шанс выигрыша
- `panic_base` — базовая вероятность паники
- `panic_lucky_scale` — коэффициент влияния удачи на вероятность паники
- `self_attack_base` — базовая вероятность гуся атаковать самого себя
- `self_attack_lucky_scale` — коэффициент влияния разницы удачи на self-attack
- `flock_min_size` — минимальный размер стаи
- `flock_max_size` — максимальный размер стаи

### Веса событий

Параметр `event_weights` управляет частотой событий (чем больше вес, тем чаще событие):

- `bet` — игрок делает ставку
- `goose_attack` — гусь атакует игрока или себя
- `flock_create` — несколько гусей объединяются в стаю
- `flock_disband` — стая распадается на отдельных гусей
- `panic` — игрок впадает в панику и теряет все деньги

## Архитектура

Проект следует принципам чистой архитектуры с разделением на слои:

- `domain` — доменные модели (Player, Goose, Effect, Entity)
- `usecase` — бизнес-логика (Casino, интерфейсы)
- `repository` — реализации хранилищ (InMemory коллекции, статистика)
- `adapter` — адаптеры ввода-вывода (CLI, отчеты)
- `test` — unit-тесты

Основные абстракции:

- `Entity` — базовый протокол для всех сущностей (игроки, гуси)
- `BalanceInterface` — протокол для сущностей с балансом
- `PlayerCollection`, `GooseCollection`, `CasinoBalance` — протоколы для хранилищ
- `CasinoStatistic` — протокол для сбора статистики

## Механика удачи

Удача (lucky) является ключевым параметром для всех сущностей и влияет на исходы большинства событий:

**Для игроков:**
- Увеличивает шанс выигрыша ставки: `P(win) = bet_win_base + player.lucky * bet_win_lucky_scale`
- Снижает вероятность паники: `P(panic) = panic_base - player.lucky * panic_lucky_scale`
- Влияет на вероятность self-attack гуся при столкновении

**Для гусей:**
- Влияет на вероятность атаковать себя вместо игрока
- Чем выше разница `goose.lucky - player.lucky`, тем ниже шанс гуся промахнуться

Все вероятности ограничиваются диапазоном `[0.0, 1.0]` через функцию clamp.

## Механика банка казино

Банк казино может уходить в отрицательные значения при крупных выигрышах игроков. Отрицательный баланс интерпретируется как заёмные средства (кредитная линия), которые казино привлекает для обеспечения ликвидности и выплаты выигрышей.

В долгосрочной перспективе математическое ожидание настроено в пользу казино за счёт:
- Базовой вероятности выигрыша ставки ниже 50%
- События паники, при которых весь баланс игрока переходит казино
- Низкой частоты событий с крупными множителями выплат

Таким образом, временные просадки компенсируются накопительным эффектом множества мелких проигрышей и редких, но значительных событий паники.


## Механики симуляции

### События

На каждом шаге симуляции выбирается одно событие согласно весам из конфигурации:

**bet** — игрок делает ставку:
- Выбирается случайный игрок с балансом больше нуля и без эффекта оглушения
- Размер ставки случайный в диапазоне от минимальной до максимально допустимой доли баланса
- Вероятность выигрыша зависит от удачи игрока
- При выигрыше множитель выплаты случайный, деньги выплачиваются из банка казино
- При проигрыше деньги ставки остаются в банке

**goose_attack** — гусь атакует:
- Выбирается случайный гусь и случайный игрок
- Вероятность атаки на себя зависит от разницы удачи гуся и игрока
- Атакующий гусь наносит урон и крадет деньги
- Кричащий гусь оглушает цель на несколько ходов
- Стая применяет эффекты всех гусей в составе

**flock_create** — создание стаи:
- Выбирается случайное количество гусей
- Гуси удаляются из коллекции и заменяются одним объектом стаи
- Стая объединяет возможности всех входящих гусей

**flock_disband** — распад стаи:
- Выбирается случайная существующая стая
- Стая распадается, исходные гуси возвращаются в коллекцию

**panic** — паника игрока:
- Выбирается случайный игрок с балансом больше нуля
- Вероятность паники обратно пропорциональна удаче игрока
- При панике весь баланс игрока переходит в банк казино

### Типы гусей

**WarGoose** — атакующий гусь:
- Обладает параметром силы (strength)
- При атаке игрока наносит урон равный силе и крадет деньги
- При атаке на себя наносит урон самому себе

**HonkGoose** — кричащий гусь:
- Обладает параметром громкости (honk_volume)
- При атаке игрока оглушает его на количество ходов, пропорциональное громкости
- При атаке на себя оглушает себя
- Оглушенные сущности не могут совершать активные действия

**FlockGoose** — стая гусей:
- Содержит коллекцию атакующих и кричащих гусей
- При атаке применяет эффекты всех гусей в составе последовательно
- Может объединяться с другими гусями через оператор сложения

## Система эффектов

Эффекты управляются через `EffectEngine` и применяются к сущностям на определенное количество ходов:

**StunEffect** — оглушение:
- Имеет источник (кто оглушил), цель (кого оглушили) и длительность
- На каждом тике длительность уменьшается
- Казино проверяет наличие эффекта оглушения и запрещает оглушенным игрокам делать ставки

**OnceStealBalance** — кража денег:
- Имеет источник (кто крадет), цель (у кого крадут) и сумму (дельту баланса)
- Срабатывает один раз на первом тике
- Используется атакующими гусями для перекачки денег от игрока к себе

**EffectEngine:**
- Хранит все активные эффекты
- Позволяет добавлять новые эффекты
- Проверяет наличие конкретного типа эффекта на сущности
- На каждом тике вызывает обработчики всех эффектов и удаляет истекшие

## Интерфейсы

**Entity** — базовый протокол для всех сущностей.

**PlayerCollection, GooseCollection** — протоколы для коллекций с методами добавления, удаления и итерации.

**CasinoBalance** — протокол для хранилища балансов.

**CasinoStatistic** — протокол для сбора статистики с обработчиками всех игровых событий:
- Инициализация казино
- Начало каждого шага
- Выбор события
- Обработка ставок, атак, создания стай
- Конец шага
